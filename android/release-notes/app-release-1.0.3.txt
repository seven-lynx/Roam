Roam 1.0.3 Release Notes

Version: 1.0.3
Release Date: June 2, 2026
Status: Beta testing via Firebase

Stability update: This build fixes critical UI crashes, improves queue handling to prevent dead URL sequences and repetitive content, polishes the overall user experience, and introduces page-load performance improvements.

What's new
- Menu tap-to-close crash prevention — Fixed crash when rapidly tapping the menu to open and close; now debounced with proper state handling to prevent race conditions
- Config sheet UI improvements — Fixed config sheet handle tap behavior and improved state synchronization for reliable sheet expansion/collapse
- Queue domain deduplication — Queue now intelligently skips candidate URLs if a same-domain entry already exists in the queue, preventing rapid-fire serves from the same website and eliminating post-thumbs-down dead URL sequences
- Root-domain pattern matching — Enhanced suppression system now matches parent domains across all subdomains (e.g., rating down artist1.bandcamp.com also suppresses artist2.bandcamp.com, user1.github.com also suppresses user2.github.com)
- Domain muting cooldown enhancements — 1-hour cooldown on domain muting now applies consistently in Discovery and Focus modes (not in Collections mode where you intentionally selected specific domains)
- Registrable domain extraction — When excluding a domain, app now extracts registrable domain (last 2 parts) instead of full hostname, blocking all subdomains at once
- Smart loading overlays — Loading overlay no longer shows for user-initiated navigation within a page—only displays when loading the actual roam URL itself, preventing interference with prefetch queue
- Network timeout improvements — Removed overly aggressive premature timeouts (8-10s) that were causing startup failures on slow networks where DNS + TLS handshake alone exceed that threshold; now relies on Ktor's 60s per-request timeout for appropriate protection
- Prefetch validation — Restored parallel validation of up to 3 prefetch URLs simultaneously for faster queue population
- Code cleanup — Removed deprecated discoveryMode code as part of Focus mode transition for cleaner codebase and reduced maintenance surface
- Background page preloading (opt-in) — New "Preload next page" setting loads the next queued URL in a hidden background WebView while you're reading the current one, warming the cache so the loading overlay clears significantly faster on subsequent roams
- Queue size and throughput improvements — Hot queue expanded from 10 to 12 slots and warm-fill batch size increased, reducing fallback-to-API frequency for rapid tappers
- Loading overlay flash fix — Overlay now waits for the page to fully commit before dismissing, eliminating the flash of the previous page's content that appeared briefly after the overlay disappeared

Bug fixes and quality improvements
- Menu gesture handling — Added debouncing and error handling to prevent rapid tap crashes; now checks for both Expanded and PartiallyExpanded sheet states
- Loading overlay polish — Fixed flash of old URLs when loading screen clears; tracks lastLoadedUrl to keep overlay up until WebView finishes rendering; doesn't display for user-initiated in-page navigation
- Registrable domain extraction — When excluding a domain, app now extracts registrable domain (last 2 parts) instead of full hostname, blocking all subdomains at once
- Configuration sheet state — Properly collects showConfigSheet state from ViewModel; uses partialExpand() instead of hide() to avoid IllegalStateException
- Offline queue robustness — Improved queue deduplication logic to prevent serving same-domain URLs in succession
- Network timeout handling — Removed overly aggressive 8-10s timeouts on repository functions that were causing false timeout errors on cold networks (DNS + TLS can exceed this); Ktor's 60s per-request timeout provides appropriate baseline
- Prefetch validation efficiency — Restored parallel validation to 3 URLs simultaneously for faster queue population without excessive memory pressure
- Domain muting consistency — Fixed muting behavior to apply appropriate cooldown in Discovery/Focus modes while maintaining full muting in Collections

Testing focus areas
1) Menu crash — Rapidly open and close the menu (tap gesture mode)—verify no crashes and smooth state transitions
2) Queue deduplication — Roam several times from the same domain (e.g., bandcamp)—verify new URLs come from different domains, not rapid serves from same site
3) Config sheet — Tap config sheet handle to expand and collapse—verify smooth animations and no state desynchronization
4) Root-domain suppression — Rate down a subdomain (e.g., artist1.bandcamp.com), roam, verify other subdomains from same parent are suppressed
5) Loading behavior — Load a heavy page with embedded media—verify no flash of previous page content and overlay doesn't interfere with user navigation
6) Domain muting cooldown — Mute a domain in Discovery mode, verify 1-hour cooldown applies; switch to Collections and verify muting still works as expected
7) Prefetch queue performance — Rapidly roam multiple times—verify queue populates quickly (parallel validation should speed this up)
8) Startup on slow networks — Disable Wi-Fi, switch to slow 4G/LTE, restart app—verify app doesn't timeout during startup, successfully loads roam data
9) User navigation within page — Load a roam URL, click links within the page—verify loading overlay doesn't appear for user-initiated navigation
10) Offline workflow — Disable network, rate URLs, roam, check exclusions—re-enable network and confirm all queued actions sync without issues
11) Back navigation — Navigate freely, then use system back button—verify consistent stack behavior and no crashes
12) Background preload (opt-in) — Enable "Preload next page" in Settings → Browser; roam several times on WiFi—verify the loading overlay clears noticeably faster after the first tap; verify no ANR or excess memory pressure; toggle off and confirm no background network traffic
13) Overlay flash — Roam repeatedly; verify the loading overlay dismisses cleanly onto the new page's content with no flash of the previous page visible

Feedback

- Queue behavior feedback especially welcome—let us know if domain deduplication feels appropriate
- Config sheet state issues should include device model and Android version
- Loading overlay flash reports should include page load time and media type
- Domain muting cooldown feedback on timing (1 hour) and when it should apply
- Startup performance reports on slow networks (4G/LTE)—include network type and DNS/TLS negotiation times if possible
- Prefetch queue speed improvements feedback—does parallel validation feel faster?
- Background preload feedback—does enabling it make a perceptible difference? Any data-usage concerns?
- Include device model, Android version, RAM for any UI/performance issues

Known limitations
- Beta build; behavior may evolve based on feedback
- Menu debounce has a brief delay (50ms) to prevent race conditions; this is intentional
- Queue deduplication uses registrable domain logic (last 2 parts)—some multi-level domains may still show repetition
- Network timeout baseline is 60s per request (Ktor); on very slow networks with transient connectivity this may still timeout
- Prefetch validation parallelization is limited to 3 URLs to avoid excessive memory pressure on lower-end devices
- Domain muting cooldown applies per subdomain; root-domain suppression applies across all subdomains (different semantics intentional)
- Offline queue persists across app sessions but is cleared on app uninstall
- Background preload is off by default to avoid unexpected data usage; the preloaded page uses the same WebView disk cache as the main browser
- Background preload only warms the cache for the immediately next queued URL; cold starts (empty hot queue) still show the normal loading overlay
